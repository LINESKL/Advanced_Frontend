## 2. Конкретные промпты

### Промпт 1:
"Объясни разницу между SSR, SSG и ISR в Next.js. Когда использовать каждую стратегию?"

**Что получил:** Подробное объяснение трех стратегий рендеринга: SSR рендерит на каждом запросе (всегда свежие данные), SSG генерирует HTML при сборке (максимальная производительность), ISR обновляет статические страницы через заданный интервал (баланс между производительностью и свежестью данных).

### Промпт 2:
"Как использовать `generateStaticParams` для динамических маршрутов в Next.js App Router? Покажи пример с блог-постами."

**Что получил:** Пример функции `generateStaticParams`, которая возвращает массив параметров для предварительной генерации всех страниц постов при сборке. Понял, что это замена `getStaticPaths` из Pages Router.

### Промпт 3:
"Как принудительно использовать SSR в Next.js App Router для страницы профиля пользователя?"

**Что получил:** Использование `export const dynamic = "force-dynamic"` для отключения кэширования и рендеринга на каждом запросе. Также узнал про альтернативу через `revalidate = 0`.

## 3. Модификация и проверка
- **Структура данных:** Самостоятельно создал типы TypeScript для Post, Author и User с правильными интерфейсами.
- **Mock API:** Разработал функции в `lib/api.ts` с имитацией асинхронных задержек для реалистичного поведения.
- **Навигация:** Интегрировал компонент Link из Next.js для клиентской навигации без перезагрузки страницы.
- **Стилизация:** Использовал Tailwind CSS для создания адаптивного интерфейса с hover-эффектами и transitions.

## 4. Что узнал
- Понял, что в App Router все компоненты по умолчанию серверные, что упрощает работу с данными.
- Изучил разницу между `revalidate` (ISR) и `dynamic = "force-dynamic"` (SSR).
- Научился использовать `generateStaticParams` для предварительной генерации динамических маршрутов.
- Понял важность выбора правильной стратегии рендеринга в зависимости от типа контента.
